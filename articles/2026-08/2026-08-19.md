## Agent 与开发工具
- **OpenViking**（2026-08-19 · `社区热度`）：火山引擎开源的「自进化上下文数据库」，把 Agent 记忆、知识 RAG、Skills 统一成 `viking://` 虚拟文件系统，内容按 L0（摘要）/L1（概览）/L2（细节）分层按需加载以省 token；官方评测 LoCoMo 上三款 agent 的原生长记忆 24-57% 提升到 80-83%、输入 token 下降 34-91%，tau2-bench 任务成功率 +6.87/+11.87pp；AGPLv3，可接 Claude Code/Codex/OpenClaw/pi 等；今日 GitHub Trending（约 2.9 万 stars）[github.com/volcengine/OpenViking](https://github.com/volcengine/OpenViking)
- **ai-memory**（2026-08-19 · `社区热度`）：面向 coding agent 的长期记忆工具——用 lifecycle hook 捕获会话，按项目沉淀成 git 版 Markdown 知识库（无向量库），并生成跨工具交接的 handoff（“Claude Code 中途退出、Codex 在同一目录接着干，不用重讲架构”）；Rust 编写、MIT，支持 Claude Code/Codex/OpenCode/Cursor/Gemini CLI/Pi/OMP 等十余款 agent；今日 GitHub Trending（约 2.7k stars）[github.com/akitaonrails/ai-memory](https://github.com/akitaonrails/ai-memory)

## 研究雷达
- **Don't Drop the BATON**（2026-08-17 · `论文原文`）：长程机器人操作里冻结 VLA、由 LLM agent 主导——以子任务为探索单元（让成本从累乘的 T^K 变为累加 T×K，每个失败都能归因到单一阶段），并引入「转换感知记忆」（verifier agent 控制 VLA 仅在场景就绪后调用、跨子任务 handoff 恢复被前序残留破坏的入口状态、lookahead 选择可被后继继承的策略）；在 RoboMemArena 上任务成功率 +11.6%、累计成功率 +14.9% [arxiv.org/abs/2608.16889](https://arxiv.org/abs/2608.16889v1)

## 今日可执行
- 想解决“换 agent 就失忆”（Claude Code ↔ Codex 来回切），**ai-memory** 轻量直接、正好贴合你的场景；想要统一记忆/RAG/Skills 的更重方案可评估 **OpenViking**（需自部署）。
- 这两款工具的共同思路——别把全部历史一股脑塞进上下文、按需按层加载——正是这一波 Agent 记忆/成本优化的大方向。
