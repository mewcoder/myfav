神圣三位一体 - pi、herdr 和 opencode go

简要概括；我目前的人工智能编码设置是 Pi、Opencode Go 和 Herdr

今年，我们正在见证工具链工程（harness engineering）的繁荣。最初只是围绕 LLM 的简单脚手架，如今已发展成为最精密、最抢手的系统之一。与此同时，LLM 也变得越来越有能力承担更多的编码和软件工程任务，从单纯的助手和补全工具演变为代码库的全面驱动者。模型不仅变得更强大，而且在成本方面也变得更加可及。例如，OpenAI 早期的推理模型，如 GPT-4 以及 O 系列，每百万 token 输出的成本高达 60 美元或更多。现在，具有类似能力的模型每百万 token 仅需约 10 美元，而且一些开源方案甚至以更低的价格提供更好的性能。

去年年初，随着 Claude Code 的发布，一切都改变了。它是第一个面向编码任务发布的重大工具链。Co-pilot 之前就存在，但它更多是作为一个聊天助手，而非能够在代码上执行操作的代理。自那以后，我们已经看到了数百个工具链的发布。每一个都在前代产品的弱点上迭代，几乎（几乎）完善了当今的流程。剩下的差距主要集中在缺乏个性化，以及缺乏对特定公司和工程师的软件工程工作流的理解。此外，还有一些应用领域存在真正的局限性，比如涉及大量硬件和固件开发的领域，由于我在这方面知识不多，因此无法评论。但对于软件工程中的所有差距，如今许多工程师正在通过构建代理工作流、工具、技能和扩展来继续填补这些空白。

在这篇文章中，我想分享我自己的设置、实验，以及哪些方法对我有效、哪些无效。如前所述，当前系统的一个差距是缺乏个性化，所以请谨慎参考。我的设置对我有效，但可能对你不适用，或者你可能有一套更适合自己的设置。归根结底，理念是不断摸索，找到最适合自己的方案，并据此进行构建。我只是想强调，当你想为自己构建某些东西时，有哪些思路和路径可供选择。

## 工具链

工具链就是护城河。工具链就是系统。无论你构建什么，无论你投入多少精力，一切都取决于你选择在哪个工具链之上运行。如今有数百种选择，而最流行的仍然只有其中的八到十个。Claude Code 一直是一个脱颖而出的工具链，但自那以后，也出现了一些在其基础上改进和迭代得非常好的产品。

当我第一次开始使用 AI 进行编码时，我在一家使用 Github Co-pilot 的大型公司工作。对我来说，任何超越 Co-pilot 的选择都是一种升级。并不是说 Co-pilot 不好，而是它有很多需要改进的地方，至少在我去年使用它的时候是这样。

## 工具链的解剖

## Pi - 极简主义之王

pi 编码代理迅速成为最受欢迎的选择之一。原因在于它崇尚极简主义，而非开箱即用的构造，其他一切都可以作为扩展添加。最棒的一点是，pi 可以根据用户的请求编辑和扩展自身。它可以完全访问自己的提示词、自己的工具，以及一个它可以自行构建的扩展库。从长远来看，随着工作流不断演变，工具链需要跟上步伐，这种能力变得至关重要。

### 设置 Pi

设置 Pi 是一个有趣的练习，因为你基本上是在与一块白板合作。它原生不支持子代理（subagents）、MCP 服务器或插件这些概念。但你确实可以得到的是扩展。你可以要求 Pi 为自己构建一个扩展，或者使用 Pi 包管理器，它允许安装开源扩展。你不仅可以定制和扩展它的能力，还可以自定义 TUI 本身，使其更适合你的工作流。

以下是我使用的扩展列表：

- **pi-mcp-adapter**：允许代理循环连接到 MCP 服务器。我喜欢保持最小化，因此我只使用 context7，它可以查找框架和库的最新文档；另一个是 Pydantic logfire，它可以实现更顺畅的调试。
- **pi-web-access**：这是必需的，因为能够访问网络正是代理最初出名的核心能力之一。同样，你可以根据需要随意定制，无论是查看其他选项还是自行构建。
- **graphify-pi**：允许代理为代码库和知识库生成知识图谱，并提供查询这些图谱的能力。对于文档编写、搭建其他代码库以及构建个人知识库非常有用。

还有一些较小的扩展，如 raw-paste、usage-extension 和 files-widget，但这些大多足够简单，更适合我的工作流。上面列出的那些，我推荐使用。

还有一些技能列表，这些技能并非 Pi 专属，但随着你不断深入，它们在大多数工程任务中也会变得非常重要。有些事情你会反复做，最好通过技能为它们创建工作流。以下是我使用的一些技能：

- **caveman**：一个非常简单的想法，但效果非常显著。本质上，模型像"穴居人"一样说话，因此使用更少的 token（《办公室》S8 E2）。在某些情况下，同样的输出可以节省高达 65% 的 token（根据其 GitHub 仓库的声称）。
  少言胜多言
- **herdr**：Herdr 是一个终端复用器，就像 tmux，但专门为代理设计，这个技能基本上允许 Pi 代理控制终端。更多内容将在本文后面介绍。
- **session-recap**：如果你进行长时间会话，在每次输出结束时有一个回顾非常有帮助，让你始终保持在循环中。
- **skill-creator**：这是一个教代理如何创建更多自定义技能的技能。它并非强制要求，但有助于代理保持其创建的所有技能的简洁性和一致性。
- **grill-me**：如果你在保持对项目的理解方面遇到困难，这个技能非常适合你。基本上，每当你要求代理做计划时，它都会用问题来反问，以确保计划深入且包含所有正确的细节。这是 Matt Pocock 众多技能中的一个，你一定应该看看他的其他一些贡献。

PI 还可以访问自己的系统提示词和工具，随着你的深入使用，你将有能力随时自定义这些内容以适应你的工作流。目前我没有在这里做任何自定义，因为我喜欢保持基线能力的最小化，并将所有自定义限制在扩展和技能上。

我喜爱 PI 编码代理的原因在于，用 AI 编码以及 AI 本身，一直以来都被宣传为一种可以为你个性化的实体。到目前为止，在所有其他编码工具链中，无论它们多么强大，情况都不是这样。你总是需要适应这些代理的工作方式，但 PI 被证明是第一个能够轻松适应我的工作流和风格的。

这几乎开始听起来像一篇赞助文章了，但我向你保证不是。Pi 在 token 使用效率和成本方面也表现出色。Composio 的一项详细研究在相同的任务集上测试了几种工具链，发现 Pi 在最低 token 使用量和最短完成时间方面一直名列前茅。

## LLM 订阅

除了 Harnesses 之外，如今还有一些选项可以让你访问几个高性能 LLM 的网关。有些是针对特定提供商的，比如 Claude Pro/Max 或 Codex Pro/Plus 订阅，后者可以访问 OpenAI 模型。
还有一些与提供商无关的选项，在我看来，这应该是当今的首选。我个人使用 opencode go，它还提供了一个 zen 版本。其他一些流行的选项包括：

ollama cloud
command code
cline
……以及更多

同样，这个选择在很大程度上取决于你愿意支付多少，以及哪些模型最适合你。不同的模型对不同的风格有不同的反应，因此这是你需要不断试验的事情。

目前对我非常有效的是 Opencode Go 订阅，它在价格上相当便宜（每月10美元），并且在开源模型上提供了非常慷慨的使用量。我一直在广泛使用新的 Deepseek v4-flash 和 v4-pro 模型，以及 GLM 模型。即使重度使用，我也从未达到会话限制（这也归功于我设置的其他部分，比如技能，以及我使用 Pi agent 的事实，它非常节省 token）。我还有 Claude Pro 订阅（主要用于聊天和协作），只在需要非常繁重的推理工作时使用。

Opencode 还提供 Zen 版本的订阅，基于使用积分。它比 Go 版提供更多模型访问权限，但由于按使用量计费，可能会很快变得昂贵。

Herdr：面向代理的 tmux

今年我的一个重点是转向更基于终端的编码设置。我从使用 VS Code 和 Cursor 转向了 neovim。如果你在这个生态系统中工作，你一定非常熟悉 tmux，它是一种终端多路复用器。它基本上允许终端会话在窗口和窗格中持久协同工作。在终端上工作也让我更好地使用 Opencode 和 Pi，因为它们主要通过终端上的 TUI 工作。

Herdr 是一款新的终端多路复用器，专门为代理而构建。它允许更轻松地与工作区交互，工作区封装了窗格和窗口，并设置 git worktree 作为主工作区的子工作区。它还能清晰地列出所有活动的代理，并将进行中、需要干预或已完成任务的代理分类。

最棒的部分来了。它内置了一个编码代理可以用来控制 Herdr 的技能。这就是我不使用任何允许在 Pi 中运行子代理的扩展的主要原因。由于 Pi 可以使用 herdr，它可以启动其他 Pi 实例，甚至其他代理来卸载和委派一些任务。这创建了清晰的关注点分离。一个编排代理可以有效地在自己的 worktree 中启动多个代理，你可以轻松地在每个工作区之间导航。没有子代理在后台运行，这使得验证输出更容易。

herdr 的潜力巨大。我建议你亲自去了解一下，并做一些实验。

神圣三位一体

我的当前设置包括：

Pi 用于 harness
Opencode Go 用于访问 LLM
Herdr 用于编排和交接

这远非完美，因为我仍在每天打磨它。但到目前为止，这让我在自动化速度和掌控之间取得了良好的平衡。代理们承担了更多责任并并发工作，但我仍然能够通过工作流程进行验证和纠正。

正如我之前提到的，这对我和我自己的工作风格有效。这可能不一定对你同样有效。我希望你能从中体会到的核心是试验，构建定制化工作流比以往任何时候都更容易。玩得开心！
